# Внесение изменений

1. Создай отдельную ветку и опиши конкретный сценарий.
2. Для нового метода проверь официальную документацию, типы токенов и реальные права. Добавь параметры в воспроизводимый сборщик каталога, не только в готовый JSON.
3. Чтение добавляй в явный allowlist после проверки побочных эффектов. Финансовые изменения и настройки безопасности требуют отдельного проектирования.
4. Для изменения VK используй неизменяемое ожидающее действие и браузерное подтверждение. Не добавляй MCP-флаг для обхода подтверждения.
5. Добавь тест на реальную границу поведения, запусти весь набор и обнови `docs/VALIDATION.md`.
6. Проверь, что в diff нет `.secrets`, токенов, баз данных, cookie или личных выгрузок VK.

Не включай секреты в issue, pull request или журнал ошибок. Для уязвимостей используй приватный канал владельца репозитория, если он настроен. Отдельный публичный адрес для сообщений о безопасности пока не назначен.
