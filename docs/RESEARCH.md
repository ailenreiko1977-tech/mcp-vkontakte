## Существенные наблюдения по коду

**ilyautov.** В `vk_mcp/server.py` константа версии VK встречается в справочном тексте, но не добавляется к запросам конфигурацией клиента. В проверенном `schema_mcp_core/client.py` нет конфигурационного поля `default_query`. Поэтому упоминание автоматического `v=5.199` не подтверждается этой связкой исходников. Наш клиент всегда добавляет версию и токен после пользовательских параметров.

Инструмент `vk_get_raw` проверяет безопасность по HTTP-глаголу и допускает произвольный путь. Для VK этого недостаточно: изменение определяется именем метода VK. Возможный обход через изменяющий метод, доступный по GET, требует отдельной проверки с подставным транспортом; реальных записей при исследовании не делали. Наш сервер вообще не предоставляет raw-инструментов.

`confirm_write=true` и дополнительные флаги передаются аргументами инструмента. Такие флаги сама модель технически может заполнить; они не являются независимым подтверждением человека. В нашем варианте ожидающее действие связано с OAuth-пользователем, точными параметрами и ревизией подключения; подтверждение находится в браузерной форме с CSRF.

**bulatko.** В исходниках есть разделение ключей для разных возможностей, обработка кодов VK, ограничение времени запросов, тесты реального MCP-протокола. Это полезные инженерные решения. При этом загрузчики принимают URL или путь к файлу и затем читают данные через `fetch` либо `readFile`. Для локального доверенного запуска и общего VPS это разные границы доступа. Наш прототип не принимает такие источники медиа. Код, проверяющий права токенов, полезен как подсказка; его результаты не заменяют проверку наших токенов.

**SCom-82.** Просмотрены клиент, регистрация инструментов и мониторинг. Клиент читает `localPath` через `readFile` без корня разрешённых файлов. В `fetch` нет явного таймаута. В `VkApiError` передаются `request_params`; дальнейшее отображение ошибки нужно контролировать, чтобы параметры авторизации не попали в ответ. Набора автоматических тестов в скачанном дереве нет. Наш код ограничивает время и размер ответа, не возвращает необработанный объект ошибки VK.

**Почему не theYahia в тройке.** Он компактнее, но в проверенном `src/index.ts` HTTP-обработчик использует один транспорт и один сервер с общим токеном; проверки пользователя перед `handleRequest` не видно. Для публичной эксплуатации с разными VK-аккаунтами это недостаточная основа. Число звёзд не использовалось как оценка безопасности.

## Что заимствовано в нашем проекте

Отбор бизнес-разделов взят из MIT-каталога ilyautov; параметры собраны заново из официальной схемы VK, добавлены разделы друзей, ленты, реакций, опросов и историй. Идеи диагностики и работы с сообществами учтены при проектировании. Исполняемый код трёх серверов не объединялся и их зависимости не запускались.

## Границы исследования

Это статический разбор и тестирование нашего кода с подставными ответами. Аудит зависимостей по базам уязвимостей, пентест, запуск кандидатов с реальными VK-токенами и проверка всех методов не выполнены. Утверждение «вредного нет» этим исследованием доказать нельзя. До публичного запуска нужны отдельная проверка токенов и OAuth, нагрузочный прогон и обновление зависимостей по актуальным уведомлениям безопасности.
