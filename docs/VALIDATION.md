## Каталог

434 метода в каталоге: **146 чтение**, **174 подготовка с подтверждением**, **114 отключены**. Это объём программного каталога, не количество проверенных рабочих вызовов на VK. В MCP представлены 8 инструментов и один сценарий-промпт. Поиск, описание и вызов методов общие, чтобы не добавлять сотни отдельных инструментов.

Основой служит зафиксированная схема VK API 5.199.99; идентификаторы ревизий есть в `vk_mcp/data/catalog.json` и исследовании. Есть явная поправка отсутствующего в схеме `wall.get.owner_id`. Неизвестные параметры запрещены; зарезервированные поля авторизации нельзя подменить.

## Выполнено

- Протокольная инициализация MCP, список инструментов и вызов поиска через реальный ASGI HTTP-обработчик.
- Отказ без OAuth-токена и выдача protected resource metadata.
- Проверка подписей JWT и отказ при неправильном issuer, audience, scope, истечении срока, неподдерживаемом алгоритме.
- Изоляция секретов, действий и страниц подтверждения между пользователями.
- Проверка шифрования токенов в базе и отсутствия их в ответах инструментов.
- Однократное выполнение при конкурирующих подтверждениях, отказ после истечения срока, отказ при смене подключения.
- Проверка CSRF/Origin и ограничения тела запроса.
- Проверка фиксированного адреса VK, отказа от перенаправлений, безопасного отображения ошибок.
- Проверка повторов для чтения при ограничении частоты и отсутствия повторов изменений.
- Расчёты аналитики на исходных числах, пропуски и нулевые знаменатели, дубликаты, закреплённые записи, ссылки на источники.

## Ещё не выполнено

- Публичная регистрация, восстановление пароля и настройки каждого конкретного MCP-клиента. Сам вход через настоящий Keycloak уже проверен.
- Реальные вызовы VK для личной страницы, сообщества и сторонних публичных стен.
- Совместимость всех функций на телефоне, в Windows и облачных клиентах.
- Восстановление резервной копии и нагрузочный тест. Docker Compose и HTTPS уже проверены на VPS.
- Проверка актуальных правил VK и условий обработки данных для публичного сервиса и анализа сторонних сообществ.
- Независимый аудит безопасности и проверка зависимостей по актуальной базе уязвимостей.

Тесты не дают гарантии отсутствия вредных последствий или ошибок. Публикация исходников возможна как прототип; открывать общий сервис до закрытия перечисленных проверок преждевременно.

## Исправление сохранения подключения

Глобальная политика `no-referrer` могла приводить к `Origin: null` в обычной браузерной POST-форме. Она заменена на `strict-origin`, которая сохраняет HTTPS origin и не передаёт путь или параметры страницы. Строгая проверка Origin и CSRF сохранена. Добавлены проверки отклонения отсутствующего, null и чужого Origin, а также успешного сохранения с корректными Origin и CSRF. Источник поведения браузера: [MDN Referrer-Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header).

## Страница проверки пользовательского доступа

Добавлены 3 проверки JavaScript (Node.js): запрос разрешений только по нажатию; только scope groups; отсутствие копирования при отказе поиска. Дополнительные Python-проверки подтверждают изоляцию iframe-исключения на публичной странице /vk-app и неизменный запрет встраивания кабинета. Реальная выдача пользовательского ключа VK и поиск с ним ожидают настройки размещения приложения владельцем.
