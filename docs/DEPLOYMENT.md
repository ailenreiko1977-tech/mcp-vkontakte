# Развёртывание

Шаблон подготовлен для одного VPS с Ubuntu и Docker Compose. Он ещё не запускался на VPS. Вход через API 4VPS подтверждает доступ к панели хостинга; команды внутри Ubuntu через этот API в проекте не выполняются. Для установки потребуется отдельный доступ SSH или консоль VM.

## 1. Подготовка

Перед установкой проверить существующие процессы, свободное место и порты. Не переустанавливать ОС. Для предполагаемого домена `skazkiizlesa.art` A-запись должна указывать на IP VPS. Эти адреса не зашиты в исходники: любой пользователь сможет развернуть собственный экземпляр.

Контейнеры: Caddy для HTTPS, приложение, Keycloak, PostgreSQL для Keycloak. При 4 ГБ RAM предусмотрены ограничения памяти: 2 ГБ для Keycloak, 512 МБ для приложения, 384 МБ для PostgreSQL, 192 МБ для Caddy. Это исходная конфигурация, не результат нагрузочного теста. Перед открытием регистрации нужно измерить реальное потребление и запас ОС.

Установить Docker по официальной инструкции для фактической версии Ubuntu; совместимость Docker с Ubuntu 26.04 на целевом VPS ещё не проверена. Заранее разрешить входящие 80/443 и ограничить SSH. Внешние порты БД, приложения и Keycloak в Compose не публикуются.

Использованные при проверке образы Keycloak 26.8.1, Caddy, PostgreSQL 17 и Python 3.12 закреплены по digest. Перед последующим обновлением проверить бюллетени безопасности и заменить digest после проверки новой версии.

## 2. Локальная конфигурация на VPS

В приватном рабочем каталоге с клоном репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python scripts/prepare_deployment.py --domain skazkiizlesa.art --owner-login YOUR_LOGIN
docker compose --env-file .secrets/compose.env -f deploy/compose.yaml config --quiet
docker compose --env-file .secrets/compose.env -f deploy/compose.yaml up -d --build
```

Скрипт создаёт `.secrets` с ключом шифрования, секретом cookie, паролями БД и Keycloak, конфигурацией realm. Параметр `--owner-login` необязателен: с ним создаётся первый пользователь с временным паролем и обязательной сменой при входе; пароль находится только в `.secrets/owner.json`. Скрипт откажется перезаписывать существующий каталог. Все эти файлы исключены из Git. Нельзя выполнять `docker compose config` без `--quiet` при записи вывода: развёрнутая конфигурация может содержать секреты.

Файл `.secrets/realm.json` монтируется только для чтения. На Linux Compose обычный bind mount не меняет права файла: если Keycloak не может прочитать файл, выдать группе контейнера доступ через ACL или подготовить отдельную копию с владельцем UID 1000 и режимом 0400, сохраняя исходный каталог закрытым. Проверить фактический UID выбранного образа. Не открывать весь `.secrets` для остальных пользователей.

## 3. Настройка Keycloak

Шаблон закрывает публичный `/auth/admin`. Для первоначальной настройки администратор использует SSH-туннель к отдельному временному loopback-порту контейнера или выполняет административный CLI внутри контейнера. Публично административный порт открывать не требуется. Начальный пароль находится только в `.secrets/keycloak.env`.

Создать своего пользователя в realm `vk`. Не использовать администратора master realm для обычной работы. Проверить политику паролей, защиту от перебора, настроить MFA и почту для восстановления. Шаблон поддерживает многие учётные записи, но самостоятельная регистрация закрыта до подготовки публичного сервиса. Чтобы предоставить доступ другим людям, создавать пользователей вручную; после настройки почты, подтверждения адресов и защиты регистрации можно включить регистрацию.

В realm есть клиенты:

- `vk-dashboard`: конфиденциальный OIDC-клиент кабинета, callback `<PUBLIC_URL>/callback`, PKCE S256.
- `vk-mcp-chatgpt`, `vk-mcp-claude`, `vk-mcp-codex`: публичные клиенты OAuth с PKCE S256 и scope `vk-mcp`.

У последних трёх список redirect URI **намеренно пуст**. Перед подключением скопировать точный callback из соответствующего клиента и внести его в allowlist Keycloak. Не использовать wildcard для чужих доменов. Для OAuth-клиента без поля client ID потребуется настроить совместимую регистрацию клиентов (CIMD/DCR) либо использовать поддерживаемое ручное указание ID. Общедоступный DCR без политик регистрации не включать.

Проверить, что discovery публикует S256, scope `vk-mcp`, точный issuer и что токен содержит audience `<PUBLIC_URL>/mcp`. В шаблоне audience фиксирован для этого ресурса; поддержка конкретным клиентом RFC 8707 и параметра `resource` должна быть проверена на практике. Нельзя отключать audience-проверку ради успешного входа. Политики issuer-bound callback и CIMD зависят от клиента и версии Keycloak, автоматически не предполагаются.

## 4. Первая проверка

Сначала проверить HTTPS, `/health`, discovery и отказ `/mcp` без токена. Затем выполнить OAuth в каждом клиенте, убедиться, что сессия видит только свои подключения, и добавить VK-токен через `/account`.

Проверить чтение на собственном аккаунте. Наличие списка инструментов не подтверждает права VK. Отдельно проверить публичные стены сервисным ключом, операции сообщества токеном сообщества и доступ личной страницы имеющимся пользовательским токеном API. Недоступные функции честно отмечать. Первую реальную запись выполнять только на тестовом сообществе после явного подтверждения пользователя.

## 5. Обслуживание

Запускать приложение одним процессом. Все изменения исходников идут через GitHub и тесты, затем пересборку контейнера. Перед обновлением сохранять зашифрованную базу, данные PostgreSQL и отдельную резервную копию ключей; ключи нельзя хранить рядом с доступной посторонним копией базы. Восстановление из копии ещё не тестировалось.

Для ежедневной очистки предусмотрены `deploy/vk-mcp-cleanup.service` и `deploy/vk-mcp-cleanup.timer`. Они вызывают в контейнере приложения `python -m scripts.cleanup`. Установить их в systemd, включить таймер и проверить разовый запуск. Результаты действий удаляются после истечения срока плюс сутки; отдельная политика резервных копий задаётся оператором.

Не включать логирование тел запросов, заголовков Authorization, OAuth callback query или переменных окружения. Для внешнего запуска нужны контакты оператора, окончательная политика хранения и удаления данных и проверка актуальных правил VK для выбранного использования. Эти параметры зависят от оператора и не выдумываются в шаблоне.
