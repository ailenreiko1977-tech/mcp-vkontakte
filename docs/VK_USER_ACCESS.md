# Проверка пользовательского доступа VK

Цель: проверить возможность вызова `groups.search` от имени пользователя для собственного VK-приложения. В схеме VK у этого метода указан только тип `user`; сервисный ключ текущего приложения на практике получил код 15 без уточняющего подкода. Наличие пользовательского поля в кабинете и получение любого VK ID токена сами по себе не подтверждают право на поиск.

## Проверка через VK Mini App

В проект добавлена страница `/vk-app`. Она включается только при явно заданном положительном `VK_MINI_APP_ID` в конфигурации сервера. В качестве адреса размещения мини-приложения нужно указать полный HTTPS URL этой страницы в собственном кабинете VK для разработчиков. Условия размещения и разрешения подтверждает владелец приложения; само размещение страницы не подтверждает доступ к API.

1. Открыть мини-приложение внутри VK под своим аккаунтом.
2. Нажать «Разрешить доступ и проверить поиск». Официальный VK Bridge запросит только scope `groups`.
3. После разрешения вызывается один `groups.search` по слову «нейрокино», count=3.
4. Если поиск отказал, страница показывает этап и числовой код ошибки. Ключ не предлагается к сохранению. Если доступ не выдаётся приложению, потребуется уточнить официальные условия VK; этот проект не обходит их.
5. Если поиск прошёл, пользователь может нажать «Скопировать проверенный ключ», затем добавить его в своём HTTPS-кабинете как `vk_user`, тип «Пользовательский токен API».
6. После этого отдельно проверить ключ запросом с VPS. Успех внутри VK не доказывает серверную совместимость; возможны ограничения приложения, срока и привязки токена.

## Секреты и границы безопасности

Страница использует локальную копию официального `@vkontakte/vk-bridge` 2.15.0, проверенную по SHA-512 npm-архива. Лицензия включена в `vk_mcp/web/VK_BRIDGE_LICENSE.txt`. Сценарии установки npm-пакета не запускались.

Полученный пользовательский ключ остаётся в замыкании JavaScript в памяти страницы. Он не выводится в DOM, не логируется, не сохраняется в localStorage/sessionStorage и не отправляется на наш сервер. Копирование происходит только по отдельному нажатию после успешной проверки поиска. Страница не запрашивает личные сообщения, фотографии, друзей или разрешения записи на стене.

Только публичная страница `/vk-app` разрешает встраивание доменами VK. Кабинет, OAuth-вход и подтверждения изменений сохраняют запрет встраивания. Для проверочной страницы запрещены HTML-формы и прямые сетевые соединения скриптов; общение с VK идёт через официальный Bridge и родительское окно VK. Серверного API для приёма токена этой страницей нет. Параметры запуска mini app не используются для авторизации в нашем кабинете или выбора пользователя.

В этом изменении не настроено автоматическое обновление пользовательских токенов. Их выдача и время действия определяются VK. Реальная проверка `groups.search` пользовательским ключом ещё ожидает разрешения владельца в VK.

Первичные источники: [VK Mini Apps API: запрос пользовательского ключа](https://github.com/VKCOM/vk-mini-apps-api/blob/master/src/index.ts), [VK Bridge](https://github.com/VKCOM/vk-bridge), [схема groups.search](https://github.com/VKCOM/vk-api-schema/blob/master/groups/methods.json).
