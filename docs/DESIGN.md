# Устройство проекта

## Данные и вход

Клиент MCP соединяется с HTTPS `/mcp` по Streamable HTTP. Keycloak выдаёт OAuth-токен пользователя. MCP SDK проверяет наличие авторизации; наш verifier проверяет RS256, issuer, audience, сроки и scope `vk-mcp`. Внутренний идентификатор вычисляется из issuer и subject. Аргумента `user_id`, выбирающего чужие секреты, нет.

Кабинет использует OIDC authorization code с PKCE S256. Браузер получает подписанную HttpOnly/Secure cookie с непрозрачным идентификатором серверной сессии. VK-токены и токены Keycloak не записываются в cookie. Сессия действует 30 минут. Выход удаляет серверную сессию, но не завершает все сессии Keycloak; глобальный выход настраивается отдельно.

В SQLite хранятся подключения с составным ключом `(owner, alias)`. Значения VK-токенов, параметры действий и результаты зашифрованы Fernet. Ключ шифрования находится отдельно от базы. Идентификаторы владельцев и состояния не зашифрованы. Шифрование защищает отдельную копию базы без ключа; администратор работающего VPS технически имеет доступ к секретам.

## Изменения

1. Модель вызывает `prepare_action`. Каталог проверяет разрешённость метода и JSON Schema параметров.
2. Сохраняется зашифрованный неизменяемый запрос, его SHA-256 и ревизия подключения. Создаётся ссылка на 15 минут.
3. Пользователь входит в браузере, видит подключение, метод и параметры, отмечает подтверждение и нажимает кнопку.
4. Проверяются сессия, Origin, CSRF и принадлежность действия. SQLite атомарно разрешает одну попытку.
5. Запрос отправляется в VK. Автоматического повтора изменения нет. При обрыве связи результат помечается `failed_or_unknown`: следует проверить VK перед новым запросом.

Нет подтверждения через флаг, который может передать модель. Ссылка сама по себе не разрешает действие: требуется вход владельца и отправка формы. Это не защищает от человека, который осознанно передал свой аккаунт или автоматизировал браузер с его сессией.

## Границы доступа

Адрес VK фиксирован: `https://api.vk.com/method/`. Пользователь не выбирает URL, заголовки, `access_token` или `v`. Перенаправления не выполняются. Время запроса ограничено 20 секундами, тело ответа 2 МБ, результат для чата примерно 100 тысячами символов. На пользователя действует минутный лимит. Нет `execute`, произвольного HTTP, shell и чтения файлов VPS.

Методы чтения определены явным списком. Имена `get*` сами по себе не дают права выполнения. Некоторые методы с нейтральным названием, например создание короткой ссылки, отключены. Вызовы изменения настроек безопасности и финансовых параметров отключены. Классификация находится в `scripts/build_catalog.py` и проверяется тестами; изменения каталога требуют ручного ревью.

Официальная схема VK описывает поддержку типов токенов неполно. Метаданные показываются как справочная информация. Сервисные ключи сервер не допускает к изменениям; остальные права окончательно проверяет VK. Никакой автоматический обход ограничений или получение чужих токенов не предусмотрены.

## Анализ похожих сообществ

`community_snapshot` получает ограниченную выборку доступных постов по одному периоду. Верхняя граница периода исключается. Показываются время сбора и полнота обхода. Текущая численность сообщества не выдаётся за численность в прошлом. На динамической стене нет атомарного снимка: новые посты во время обхода могут смещать страницы.

`compare_communities` также работает с переданными пользователем данными, поэтому не требует обязательного массового сбора через API. Из расчёта исключаются дубликаты и закреплённые записи. Реклама и репосты автоматически не исключаются; это явно указано в ответе. Значения реакций берутся из источника, отсутствующие показатели остаются `null`. Просмотры не равны уникальному охвату. Медиана ER считается по постам с достаточными исходными данными и ненулевым знаменателем; число таких постов возвращается отдельно.

Темы, стиль, качество визуала и гипотезы о причинах успеха интерпретирует модель. Промпт требует отделять их от измеренных данных и давать ссылки на публикации. Модуль не придумывает продажи, бюджеты, демографию или коммерческую эффективность. Для корректного сравнения нужны сообщества близкой тематики и одна общая временная выборка.

Правила VK об использовании данных следует проверить до публичного запуска аналитики. Страницы `dev.vk.com/ru/rules` и `dev.vk.ru/ru/rules` при исследовании получить не удалось; актуальная допустимость конкретного сценария не установлена. Наличие публичного API технически не подтверждает разрешение на любой способ обработки данных.

## Пока не завершено

Бинарные загрузки, Long Poll событий, фоновое расписание, выдача токенов VK через собственное приложение, полноценное удаление аккаунта вместе с данными в Keycloak и расширенная панель оператора требуют следующего этапа. Горизонтальное масштабирование не проверено; расчёт на один процесс и SQLite. Публичная регистрация в шаблоне закрыта до настройки защиты регистрации, почты и условий использования, затем оператор может её включить.
